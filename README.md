# SKU 建档工具集：生成器 + 质检器

> 拼多多电商 SKU 建档表的「生成 + 校验」双工具闭环。
> 由运营人员（非专业程序员）借助 AI 辅助编程独立开发，已在自己日常工作中稳定使用。

## 一、背景与痛点

- 电商运营每天要把若干 SKU 组合做成拼多多要求的 **17 列「建档表」**再上传平台
- 后台 ERP（聚水潭）**没有 API 权限**，数据只能手工复制粘贴
- 建档表格式硬性、一格都不能错：错了会导致 **发错货** 或 **库存分裂**
- 原来手工做一张 5 组建档表需要 **约 30 分钟，且无法保证无错**

## 二、解决方案：两个工具一对，一个生成、一个检查

```
聚水潭粘贴数据 ──▶ SKU建档工作台 ──▶ 17列建档表 ──▶ 建档表检查器 ──▶ 检查报告 ──▶ 上传
  (无API,手工复制)     (生成器)           (生成)        (质检器)        (错误/警告/提示)
```

### 1. SKU建档工作台（生成器）

三个页签即一天的工作流：

| 页签 | 功能 |
|---|---|
| ① 编码库 | 粘贴 ERP 原始数据（行列错位的父/子行结构），自动解析出「品类/货号/花色/尺码/编码」并写入 Excel 编码库；新增/跳过/冲突三种策略，冲突不覆盖 |
| ② 生成 | 一行文本描述一个组合（`货号-花色+花色 / N条装 / 尺码1,尺码2`），支持 `ALLIN` 全花色展开、`EO` 标记前后置、花色名带破折号 |
| ③ 预览/导出 | 可视化表格，红底=编码查不到、黄底=Q 列公式有风险；可双击编辑，按 17 列硬性版式导出（红字表头、组间空 10 行、自动写公式） |

核心能力：
- **三种编码族正则解析**：内裤型 `T#S#`、身高型（3 位身高码）、背心/文胸型（无 T 段），识别顺序从最严格开始
- **尺码归一**：XXL≡2XL、XXXL≡3XL
- **条数校验**：N 条装 = 各编码 T 后数字之和（不是款数、不是行数）
- **预判 Excel 公式坑**：花色码含 T 时 `TEXTAFTER(J,"T")` 会取错 → #VALUE!，自动标黄+批注提示正确值

### 2. 建档表检查器（质检器）

上传前把 17 列逐格体检，**四层 100+ 条规则**：

1. **整表**：17 列表头名称与顺序、表头样式（字体/红字/行高/列宽）、多余列、组间空行
2. **每个组合**：A 列组合部分全组一致、A=C、B 标签格式、N 条装=ΣT#、组合被拆段、尺码顺序
3. **每一行**：J 列编码非空/大写/可解析、J 尺码=A 末尾尺码（归一后比较）、编码在库中、K=1、L 列公式行号正确且组合合计=1、Q 列公式/数值校验、E~I 与 M~P 留空、字体规格
4. **按编码库反查**（最有价值）：每个「尺码×花色」是否缺行、所填编码是否属于该位置（花色顺序错=两个花色库存对调，单独报）、EO 版本混用检测、编码库自身体检

特性：
- 问题三级分类：**错误**（会发错货）/ **警告**（需人确认）/ **提示**（版式小差别），双击看「现值+应改+原因」
- 报告导出 xlsx（原表副本标色+批注，原表不动）或 txt（便于群聊传播）
- **支持命令行**：`--check --lib --out --gap --json`，退出码 0/1/2，可接入批处理流水线

## 三、成效（本人日常使用实测）

| 指标 | 之前 | 现在 |
|---|---|---|
| 5 组建档表耗时 | ~30 分钟 | 1~5 分钟（最快 1 分钟） |
| 错误率 | 无法保证 | 使用以来 **0 错发** |
| 日处理量 | — | 10+ 款式 |

## 四、技术栈

- Python 3 + openpyxl + tkinter
- 正则驱动的三族编码解析引擎
- PyInstaller `--onedir` 打包为双击即用的 Windows exe（目标机器无 Python、装 WPS）
- 业务规则沉淀为结构化文档（见 `docs/需求说明.md`，含 12 条踩坑清单，可复用于新会话）

## 五、目录结构

```
├── SKU建档工作台/          # 生成器源码
│   ├── core.py             # 解析引擎 + 生成 + 导出（无界面逻辑）
│   └── app.py              # tkinter 界面层
├── 建档表检查器/            # 质检器源码
│   └── app.py              # 四层检查规则 + 报告 + 界面 + CLI
├── docs/
│   ├── 需求说明.md          # 完整业务需求沉淀（可贴给 AI 复现）
│   ├── 项目档案-公开版.md    # 全项目上下文档案（丢给任意 AI 即可接手）
│   ├── 使用说明-工作台.txt
│   └── 使用说明-检查器.txt
└── requirements.txt
```

📄 **完整项目档案见 [docs/项目档案-公开版.md](docs/项目档案-公开版.md)**——代码架构、关键函数、踩坑清单、成果数据一站式速查，可直接丢给任意 AI 平台的新会话接手项目。

## 六、本地运行

```bash
pip install -r requirements.txt
python SKU建档工作台/app.py     # 生成器
python 建档表检查器/app.py      # 质检器（图形界面）
python 建档表检查器/app.py --check 建档表.xlsx --lib 编码库.xlsx --out 报告.xlsx
```

> 注：本仓库只含代码与文档，不包含任何业务数据（编码库、建档表、历史报告均在 .gitignore 中排除）。
