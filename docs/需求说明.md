# SKU 编码建档工具 · 需求说明（可直接贴给新会话）

> 这份文件是「内衣内裤 SKU 建档表生成器」从 0 到 v2.0 的全部结论沉淀。
> 在新会话里把这份文件丢给 AI，就能让它直接做一个「编码建档检查工具」，不用重新踩一遍坑。
> 说明：本文档中所有货号、花色码、编码示例均为虚构演示数据，与任何真实商品无关。

---

## 一、业务背景

- 电商运营，类目：内衣内裤 / 童装家居服 / 少女内衣。平台：拼多多。
- 后台 ERP 是**聚水潭**（网页版），**没有 API 权限**，数据只能手工复制粘贴。
- 每天/每批要把若干个 SKU 组合建成「建档表」，再上传平台。
- 建档表格式固定 17 列，一格都不能错，错了会发错货或库存分裂。

---

## 二、建档表格式（17 列，硬性）

| 列 | 名称 | 怎么填 |
|---|---|---|
| A | 组合商品编码 | `货号-花色+花色+货号-花色-尺码`；同组所有行填同一个值 |
| B | 组合装商品标签 | `绿色标,尺码，N条装`（**少女文胸/背心用英文逗号**：`绿色标,L,2条装`） |
| C | 组合款式编码 | 与 A 完全相同 |
| D | 组合商品名称 | 品类名，如 儿童内裤 / 少女背心 / 家居服套装 |
| E–I | — | 留空 |
| J | 商品编码 | 从编码文档查出来的实际编码，同组每行不同 |
| K | 数量 | 一律 1 |
| L | 应占售价 | `=ROUND(Q{r}/SUMIFS(Q:Q,A:A,A{r}),4)`，同组合合计 = 1 |
| M–P | — | 留空 |
| Q | 条数（无表头） | 见下 |

**表头样式**：微软雅黑 9，A/C/J/K/L 五列标题**红字**，其余黑字；行高 31。
**J 列数据**：宋体 11，无边框，垂直居中。
**列宽**：A 39.375、B 23.875、C 39.375、D 9.625、F 12.625、G 6.625、H 8.125、
J 21.625、K 3.625、L 6.625、M 8.125、N 15.625、O 3.625、Q 9.0。
**分组**：每个 SKU 组合之间**空 10 行**，最后一组后面不空。

**Q 列规则（关键）**
- 内裤型：硬门槛公式 `=LEFT(_xlfn.TEXTAFTER(J{r},"T"),1)*K{r}`，不能写死数字。
- 身高型 / 背心型：编码里没有 T 段，公式必然 #VALUE!，直接写 `1`。

## 三、三种编码族（解析核心）

### ① 内裤型
```
前缀 + 货号(3~7位) + 花色码(可空) + T#S# + 尺码
正则：^([A-Z]+)(\d{3,7})([A-Z]*)T(\d)S(\d)(.+)$
```
| 例子 | 货号 | 花色码 | T#S# | 尺码 |
|---|---|---|---|---|
| `FCS95001TAT1S13XL` | 95001 | TA | T1S1 | 3XL |
| `FWP79002T2S2M` | 79002 | （空版） | T2S2 | M |
| `FR3901TET1S12XL` | 3901 | TE | T1S1 | 2XL |

- `T#` = 该单品含几条；`S#` = 含几个颜色。`T1S1` = 1条1色。
- **N 条装 = 各组编码 T 后面的数字之和**，不是行数、不是款式个数。
  例：3 个款号分别是 T1、T2、T1 → 1+2+1 = 4 条装。

### ② 身高型（保暖套装 / 家居服）
```
款式编码 + 3位身高
正则：^([A-Z][A-Z0-9]*?)(\d{3})$，且尾 3 位 ∈ {80,90,100,110,120,130,140,150,160,170,180}
```
`MX088110` → 款式 `MX088` + 尺码 `110`；`MX086XM110` → `MX086XM` + `110`。
码数不固定，由尾 3 位识别，所以 `MX098` 本身不会被误判（074 不是合法身高）。

### ③ 背心/文胸型（少女内衣）
```
前缀 + 货号(3~5位) + 花色码(2~6位) + 尺码
正则：^([A-Z]+)(\d{3,5})([A-Z]{2,6}?)(XXXL|XXL|XL|XS|S|M|L)$
```
`B2620SJM` → 货号 `2620` + 花色码 `SJ` + 尺码 `M`；`B890JANL` → `890` + `JAN` + `L`。
**没有 T 段。**

**识别顺序必须是：内裤型 → 身高型 → 背心型**（先匹配最严格的）。

## 四、尺码归一（必须做）

| 写法 | 归一为 |
|---|---|
| `XXL` / `2XL` | `2XL` |
| `XXXL` / `3XL` | `3XL` |
| `XXXXL` / `4XL` | `4XL` |
| `XL` | `XL` |
| `S` / `M` / `L` / `XS` | 原样 |
| `110`~`180` | 原样（身高码） |

**输出时编码照抄文档原文**，不把 `2XL` 改写成 `XXL`；A 列末尾保留用户输入的写法。

## 五、数据来源：聚水潭粘贴的真实形状

从「商品及库存管理 → 按款式」框选复制，粘出来是**行式、列错位**的：

```
A列                  B列                C列                  D列
B2620深灰条纹        B2620SJM           (空)                 少女背心
B2620SJL             L;1件装;160/80     (空)                 少女背心
B2620SJM             M;1件装;155/75     (空)                 少女背心
```

- **组名一行有编码，子行第一列才是编码**（父子行错位）
- 组名可能带破折号（`R3901-藤紫`），也可能不带（`B2620深灰条纹`、`MX098`）
- C 列规格 `110码;浅绿;110/56` 里第 2 段是花色名（身高/背心型用得上）
- D 列是品类，**可能一次粘多个品类**（少女背心 + 童装），必须**按行**取，不能取全局
- 有的列全是 `999`（价格占位），不能被当成品类

**解析策略（已验证可用）**
1. 先扫全表找出所有编码格子，记下 `(行, 列) → (货号, 尺码, 族)`
2. 非编码格子，若右边或下边能找到编码 → 判定为组标题；花色名 = 标题里「货号」之后的部分
3. 编码取花色：同排左侧最近标题 → 本列上方最近标题 → 左侧各列上方最近标题
4. 身高/背心型：花色优先取同行规格里的中文段，取不到再用标题
5. 同一款式若只有一种花色，把空花色的行统一过去（避免 `MX098` 拆成两款）
6. 品类：按行找「含中文、不含分号、长度≤12、不是标题、不是编码」的格子

## 六、踩过的坑（全部已验证，新会话可直接写进需求）

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | `TEXTAFTER(J,"T")` 取第一个 T | 花色码含 T 时取到字母 → `#VALUE!`，**整组**应占售价一起废（SUMIFS 被污染） | 公式保留（是硬门槛），但生成时把这类行**标黄+批注**，批注写明「本行编码末尾是 T1S1，正确条数应为 1」 |
| 2 | 哪些编码会中招 | `TA`(天蓝)、`TKD`(坦克)、`TE`(樱桃)、`XGT`(小熊)、`WTKI`(挖土机) | 判定：第一个 T 后面不是数字 → 需手动核查 |
| 3 | 只读 B、E 两列 | 编码文档 4~6 列并排时只读到 2 列 | 逐列扫描，或改成行式解析 |
| 4 | 货号写死 5 位 | `R3901`（4位）、`890`（3位）全部匹配不上 | `\d{3,7}` |
| 5 | 组标题必须有破折号 | `B2620深灰条纹`、`MX098` 全被忽略 | 用「标题里货号之后的部分」取名 |
| 6 | 空版款号（无花色） | `FWP79002T2S2M` 被当成非法 | 花色码允许为空 |
| 7 | 前缀位数当成固定 3 位 | 把合法的 1 位前缀 `D`（`F95129QJANT1S1M`）误判为漏写 | 前缀 1~3 位都是正常的；以编码文档为准，不要自行补位 |
| 8 | 按组件个数校验条数 | 3 个款号标 4 条装被报错 | 按 ΣT# 校验 |
| 9 | 同一编码出现在两个组（空版 + 带花色） | 同一款式两个键，查不到 | 按编码去重，优先保留带花色的那条 |
| 10 | 品类的全局判定 | 一次粘多个品类时全部丢失 | 按行取 |
| 11 | `999` 被当成品类 | 品类列写满数字 | 品类必须含中文 |
| 12 | PyInstaller `--onefile` | 启动报 `Could not create temporary directory!` | 用 `--onedir`（exe 5.8MB + `_internal`），不依赖 TEMP |

## 七、工具形态（已验证的落地方式）

- **图形界面 exe**，PyInstaller `--onedir --noconsole` 打包，5.8MB，双击即用。
- 用户环境：Windows 10、装 WPS 不是 Excel、没有 Python、没有聚水潭 API。
- 编码文档用 Excel 维护，结构：
  - `①编码库` —— 唯一数据源，一行一个商品编码，列：品类/货号/花色/尺码/商品编码/花色码/备注。
    真正必填只有 **花色 + 商品编码**，其余可从编码解析；填了会做一致性校验。
  - `②贴板` —— 聚水潭粘过来的原始块，点「导入贴板 → 编码库」自动解析、去重、查冲突、补品类、刷新总览。
  - `③款号总览` —— 自动生成。
  - `④新增指引` —— 给运营看的操作说明。
  - `⑤命令行示例` —— 用户自己记 SKU 清单。

**导入时的三种结果**：新增 / 已存在跳过 / **同货号+花色+尺码出现不同编码 → 报冲突不覆盖**。
