## 二、两个工具的功能总览

### 1. SKU建档工作台（生成器）v3.2
把 ERP 粘贴数据变成拼多多要求的 17 列建档表。三个页签即一天的工作流：

| 页签 | 功能 |
|---|---|
| ① 编码库 | 粘贴聚水潭原始数据（行列错位的父/子行结构），自动解析品类/货号/花色/尺码/编码，写入 Excel 编码库；新增/跳过/冲突三策略，冲突不覆盖 |
| ② 生成 | 一行文本描述一个组合：`货号-花色+花色 / N条装 / 尺码1,尺码2`；支持 `ALLIN` 全花色展开、`EO` 标记前后置 |
| ③ 预览/导出 | 可视化表格，红底=编码查不到、黄底=Q 列公式有风险；可双击编辑；按 17 列硬性版式导出（红字表头、组间空 10 行、自动写公式） |

核心规则：
- 三种编码族正则解析：内裤型 `T#S#`、身高型（3 位身高码 80~180）、背心/文胸型（无 T 段）；识别顺序：内裤 → 身高 → 背心（先严格后宽松）
- 尺码归一：`XXL≡2XL`、`XXXL≡3XL`、`XXXXL≡4XL`；输出时照抄编码库原文
- 条数校验：N 条装 = 各编码 T 后数字之和（不是款数、不是行数）
- 预判 Excel 公式坑：花色码含 T（TA/TKD/TE/XGT/WTKI）时 `TEXTAFTER(J,"T")` 取错 → #VALUE!，自动标黄 + 批注提示正确条数

### 2. 建档表检查器（质检器）v2.0
上传前把 17 列逐格体检，四层 100+ 条规则：

1. **整表**：17 列表头名称与顺序、表头样式（微软雅黑9、A/C/J/K/L 红字、行高31、列宽）、多余列、组间空行
2. **每个组合**：A 列组合部分全组一致、A=C、B 标签格式、N条装=ΣT#、组合被拆段、尺码顺序
3. **每一行**：J 列非空/大写/可解析、J 尺码=A 末尾尺码（归一后比）、编码在库中、K=1、L 列公式行号正确且组合合计=1、Q 列公式/数值校验、E~I 与 M~P 留空、字体（J 列宋体11，其余微软雅黑9）
4. **按编码库反查**（最有价值）：每个"尺码×花色"是否缺行、所填编码是否属于该位置（花色顺序错=库存对调，单独报）、EO 版本混用检测、编码库自身体检

- 问题三级分类：**错误**（会发错货）/ **警告**（需人确认）/ **提示**（版式小差别），双击看"现值+应改+原因"
- 报告导出 xlsx（原表副本标色+批注，原表不动）或 txt
- **支持命令行**（可进批处理流水线）：
  ```
  建档表检查器/app.py --check 建档表.xlsx --lib 编码库.xlsx --out 报告.xlsx [--gap 10] [--no-style] [--loose-eo] [--json]
  退出码：0=没错，1=有错误，2=程序出错
  ```

### 关键函数速查（改代码时直接定位）

**SKU建档工作台/core.py**
- `parse_code(code)`：三族正则识别，返回 `(货号, 尺码, 族)`
- `norm_size(s)` / `size_key(s)`：尺码归一与排序
- `parse_grid(grid)`：聚水潭粘贴块启发式解析（父/子行错位）
- `parse_combo(text)`：组合文本 DSL 解析
- `build_rows(codebook, combos_text, ...)`：生成行，含 EO/ALLIN 展开与警告
- `export_xlsx(rows, path)`：按 17 列规范导出
- `write_library(path, ...)`：写入①编码库，含冲突检测

**建档表检查器/app.py**
- `class Library`：编码库加载（兼容表格版/多列粘贴版）
- `class Table`：建档表加载与分组
- `class Report`：问题收集与排序
- `check(table, lib, gap, style, strict_eo)`：主入口，四层检查
- `cli(argv)`：命令行入口
- `class App`：tkinter 界面

### 打包成 exe（发布给无 Python 环境用）

## 六、网络与中国区访问要点

1. github.com 主站在国内部分网络直连不通；`api.github.com` 一般可直连；浏览器和 git 需走本地代理
2. **下载 GitHub 资源用镜像**：
   - git-for-windows：`https://registry.npmmirror.com/-/binary/git-for-windows/v{版本}/Git-{版本}-64-bit.exe`（淘宝镜像，稳定）
   - GitHub release 加速：`https://ghproxy.net/https://github.com/...`（原链接前加前缀）
   - 已失效的镜像：ghproxy.com、ghfast.top（随时间变化，失效换新的即可）
3. winget 官方源下载 Git/gh 会因 github.com 被墙而失败（0x80072efd），走镜像手动安装
4. Git 静默安装到用户目录免管理员：`Git-xxx-64-bit.exe /VERYSILENT /NORESTART /NOCANCEL /SP- /DIR=C:\Users\<用户>\Git`
5. gh 用 zip 免安装版解压即用，路径 `gh_xxx_windows_amd64\bin\gh.exe`
6. 若使用 TUN 全局代理模式，无需 git 代理配置；用完可 `git config --global --unset http.proxy` 清理

## 九、附录：12 条踩坑清单（源自 docs/需求说明.md，新会话可直接引用）

1. `TEXTAFTER(J,"T")` 取第一个 T，花色码含 T → #VALUE! → 标黄+批注提示正确条数
2. 中招花色码：TA 天蓝、TKD 坦克、TE 樱桃、XGT 小熊、WTKI 挖土机
3. 编码文档 4~6 列并排时只读 2 列 → 逐列扫描或行式解析
4. 货号写死 5 位 → `R3901`(4位)/`890`(3位) 匹配不上 → `\d{3,7}`
5. 组标题必须有破折号 → `B2620深灰条纹`/`MX098` 被忽略 → 用标题里货号之后的部分取名
6. 空版款号（无花色）被判非法 → 花色码允许为空
7. 前缀位数写死 3 位 → 1 位前缀 `D` 误判 → 前缀 1~3 位，以编码文档为准
8. 按组件个数校验条数 → 按 ΣT# 校验
9. 同一编码出现在两组（空版+带花色）→ 按编码去重，优先保留带花色
10. 品类全局判定 → 一次多品类全丢 → 按行取
11. `999` 被当成品类 → 品类必须含中文
12. PyInstaller `--onefile` → 启动报错 → 用 `--onedir`
